# Milestone B implementation report

Implemented on `feature/ta-milestone-b` from merged Milestone A commit `11910efc8714000e05ceb4fa5200163c267eb2c1`. Milestone C and all listed non-goals remain unimplemented.

## Result

- Unauthenticated published-job list/detail and application intake have strict schemas, a honeypot, a disabled CaptchaPort, persistent IP/email limits and generic HTTP 202 acknowledgements for new/existing/duplicate candidate/application cases. Public fields are explicitly projected.
- Tenant slugs resolve through a narrowly granted SECURITY DEFINER function with a fixed search path. The function reads an owner-maintained global public slug/UUID routing directory. It neither bypasses nor relaxes RLS on tenant business tables. Runtime/PUBLIC cannot access the directory directly.
- Separate default-false CALL, RECORDING and TRANSCRIPTION choices are written to the append-only consent ledger with notice version, database time, source IP and user-agent HMAC. Public evidence has a null staff actor and is explicitly unverified. Staff-verified consent remains the only basis for existing call planning.
- Private resume uploads validate PDF/DOCX signatures/package structure, size and filenames; record SHA-256 and scanner status; and use generated keys with a local development adapter or a SigV4 S3-compatible adapter. Downloads require recruitment-role authorization, CLEAN status, matching integrity hash and a transactional audit event, then stream an attachment.
- Admin erasure anonymizes candidate PII, blocks document access, appends consent revocations, cancels planned calls and attempts document deletion. Pending deletions are explicit and retryable. The retention CLI supports tenant-scoped dry runs and bounded execution under hireai_app with an active administrator.

## Schema and grants

Migration 006 adds unique/backfilled `tenants.slug`, restricted directory/resolver/synchronization functions, `candidates.erased_at`, consent notice/IP/user-agent/verification fields and nullable public captured_by, candidate_documents and public_intake_limits. It also adds tenant-first indexes and exact grants. Both new tenant business tables use composite tenant keys, enabled+forced tenant_isolation RLS and explicit query tenant predicates. Consent/audit/stage evidence remains append-only for the runtime role. The routing directory is global, derived public metadata rather than a tenant business table and has no runtime table grants.

Migration 007 is generated by the existing enum workflow for PENDING/CLEAN/INFECTED/ERROR document statuses. All previously merged migrations 001–005 are unchanged. No runtime dependencies were added. Private local storage is excluded from Git and Docker contexts.

S3 metadata includes the uploaded object version; downloads and erasure address that version. Erasure permanently deletes the recorded version rather than only creating a delete marker. Generated keys are written conditionally to prevent overwrite.

## Decisions and limits

- Existing tenants get collision-free `tenant-<UUID>` slugs. Bootstrap can set/update a friendly slug when the tenant ID is supplied. Slug backfill temporarily removes owner FORCE enforcement inside its transaction and restores FORCE before commit; runtime tenant isolation stays enforced.
- A global routing directory avoids requiring CREATEROLE/BYPASSRLS privileges or adding a permissive tenants policy. It contains only public slug and root tenant UUID, is maintained transactionally by a fixed-search-path owner trigger, and exposes only a single resolved UUID through the function.
- An anonymous email submission is not verified identity. Existing candidate PII is never overwritten. Repeated applications do not append duplicate consent or files. New applications to a different job can append self-reported evidence; that evidence does not grant or revoke effective verified calling consent. Existing staff consent source labels remain compatible.
- IP/email limits are fixed-window, per tenant, and stored as JWT-keyed HMAC buckets in PostgreSQL (defaults 20/IP and 5/email per hour). Public Nest route throttling also applies at 30/minute per IP/handler. Expired counters are cleaned on intake/retention. CAPTCHA is deliberately disabled, not represented as active protection.
- Public JSON resumes are capped at 512 KiB decoded to preserve existing 1 MiB JSON behavior; staff multipart uploads default to 5 MiB with a 10 MiB hard ceiling. PDF/DOCX format checks are not malware scanning. The explicit scanner stub always returns PENDING; no endpoint or environment switch can falsely mark a document CLEAN. A real scan adapter is needed before documents become downloadable.
- Local storage is development/test only, with private directory/file modes. Production requires HTTPS S3 configuration and a bucket provisioned to deny public access. The adapter produces no public ACLs or public links.
- Erasure commits the candidate tombstone before external deletion. HTTP 200 includes documentsPending; only zero confirms all referenced objects were deleted. Retrying the endpoint or retention safely completes pending work. No distributed transaction or background queue is added; failed pre-commit object cleanup is logged for storage-inventory reconciliation.
- Retention defaults to 365 days, excludes recent application/consent activity, active applications and employee-linked candidates, and rechecks eligibility under the candidate lock. It retries pending erasure regardless of age. The CLI must be built first and accepts explicit tenant/admin IDs, dry-run and a bounded limit.
- Erasure covers recruitment candidate PII and resumes. Separate employee records and consent/audit/stage evidence are preserved. Legal requirements, evidence PII, notices, backups/replicas and their lifecycle must be validated with counsel.

## What was not verified

No real external S3 bucket credentials, bucket policies, replicas or backups were tested; S3 behavior was verified with a signed-protocol test server. No real CAPTCHA or malware service is implemented or contacted. No production migration, deployment or erasure was performed. GitHub CI is separate from these local acceptance checks.
